# Milestone 1.0: walking skeleton

Date: 2026-10-08

## What exists now

- **Portenv.app** (`apps/mac`, SwiftUI, run from Xcode): one window titled with the box's name and its state, a SwiftTerm terminal (MIT) in the box's tmux session, and the title menu. Only Move To ▸ (This Mac, each server) and Revert To ▸ Last Save Point work; File › Make Save Point (⌘S) makes the save point to revert to. Closing the window or quitting saves and releases the box.
- **portenvd** (`core/daemon`): serves `portenv.daemon.v1` on a 0600 socket in the Portenv directory. It opens boxes (resume rules, start), closes them (save and release), makes save points, reverts, moves boxes to a server and back, and relays terminals. When it stops, it saves and releases the boxes it opened.
- **The agent channel (ADR 0010, proposed):** `portenv-agent serve` in every box serves the agent API on TLS with a certificate made at each start and pinned by the client, plus a per-start token. The docker driver publishes it on 127.0.0.1 only. `portenvd` reaches boxes only this way: restic, path checks, readiness and terminals.
- **Revert To ▸ Last Save Point** in the sync engine: the home is saved first, with the usual lease checks, so the revert itself can be undone from history; then the newest save point is restored.
- **`core/local`:** the box environment (configs, keys, storage, sessions, the move's remote half), shared by the CLI and `portenvd`.
- Until 1.1 the app calls `portenvd` through the CLI: `portenv attach BOX` for the terminal, `portenv app ACTION BOX` for the menu.

## Tests

- `tests/e2e/daemon.sh` (in `make e2e`): open, attach lands in `work`'s tmux, save point, revert, close, reopen (rule 3). The engine's exec events show no `docker exec` into the box but its own health check.
- `tests/e2e/daemon-server.sh` against the test server: open on the Mac through `portenvd`, write files through the terminal, Move To the server (files and a 5 MB checksum intact), change a file there, Move To This Mac (rule 5, the change is back). 29.0 s to the server, including enrolling it; 21.0 s back.
- Sync: revert keeps the replaced work, keeps the lease, refuses without a save point or the lease, and survives a restore killed half way. The model test makes save points and reverts at random.
- Agent channel: wrong or missing token refused; an impostor with another certificate never receives the token; conformance over the channel (terminal in `work`'s tmux, new credentials after a restart). The only published port is the agent's, on loopback.
- `TestChannelPasswordIsUnreadable`: while restic runs over the channel with a password, the API process and restic resist root, root as `portenv-sync` and a lane user (environment, fd 3, command line, memory, ptrace). A control shows the probe finds the secret in an ordinary root process.
- `PortenvKitTests`: the box controller's open, move, revert, save point and close.

## Found and fixed on the way

- The restic password now passes through the agent. Root in a box can read the memory of any dumpable root process, so the API runs in its own process, which makes itself non-dumpable before it reads anything. Init never handles passwords.
- A pinned certificate checked only in `VerifyPeerCertificate` could be skipped on a resumed TLS session; the check now runs in `VerifyConnection`.
- `portenvd`'s graceful stop waited forever for open terminals. It now saves and releases first, then ends every call.
- The app's quit reply ran on the main actor, which AppKit does not service while it waits in its modal run loop mode. The daemon stop now runs detached, and the reply is posted into that mode.
- Unix socket paths over 104 bytes fail with "invalid argument"; `portenvd` now says the path is too long.
- `ssh portenv` landing in tmux was never checked by the 0.5 gate. It is checked now, and passed against the server.

## Demo

**On this Mac** (terminal, save point, Revert To):

```sh
make image app                                   # bin/Portenv.app, with portenv, portenvd and restic inside
bin/portenv init demo --image portenv/toolbox-node:dev
open bin/Portenv.app                             # quit with ⌘Q: it saves and releases the box
```

The app opens the box named by `PORTENV_BOX` (default `demo`); to pick another: `open --env PORTENV_BOX=NAME bin/Portenv.app`. It starts `portenvd` itself and stops it when it quits. Xcode (`open apps/mac/Package.swift`, Portenv scheme) also works; Xcode first asks to download the Metal Toolchain, because SwiftTerm ships a Metal shader: install it, or use `make app`.

In the window: type in the terminal; File › Make Save Point (⌘S); change a file; click the title (the box's name) › Revert To ▸ Last Save Point. The same actions are in the menu bar's Box menu. Quitting saves and releases the box.

**Move To ▸ a server and back** (1.0b) needs the test server running, and a box whose storage is on it (a box with storage only on this Mac cannot move). Start the server first: its address changes at every start, and the box's storage names it. The server and this Mac need the same toolbox image (here `portenv/toolbox-node:10b`, built from this branch on both; after merging, the image CI publishes).

```sh
export PORTENV_SSH="ssh -i ~/.ssh/portenv-test -o IdentitiesOnly=yes -o UserKnownHostsFile=$HOME/.ssh/portenv-test.known_hosts -o HostKeyAlias=portenv-test-gate -o StrictHostKeyChecking=yes"
HOSTKEY=$(awk '$1=="portenv-test-gate"{print $2" "$3}' ~/.ssh/portenv-test.known_hosts)
scripts/demo-server-box.sh SERVER-IP "$HOSTKEY" demo-server portenv/toolbox-node:10b
open --env PORTENV_BOX=demo-server --env PORTENV_SSH="$PORTENV_SSH" bin/Portenv.app
```

The script brings the server up to this build (portenv, the runner, the SSH user `portenv` for your key, whose sudo allows only `/usr/local/bin/portenv`) and adds `portenv@SERVER-IP` to Move To. In the window: click the title › Move To ▸ portenv@SERVER-IP. The same terminal now runs on the server (`uname -r` shows the server's kernel) and the state line says where the box runs. Edit a file there, make a save point (⌘S), change it, Revert To ▸ Last Save Point, then Move To ▸ This Mac: the box comes back with what you did on the server.
