# Milestone 0.5: server setup and the Phase 0 gate

Date: 2026-10-08

## What exists now

- **`server/setup.sh`** for Ubuntu 24.04 (arm64 or amd64): Docker Engine from Docker's repository (signing key pinned), a LUKS volume for box homes, a chrooted SFTP-only storage account, restic and rest-server on the host (checksums pinned from their signed `SHA256SUMS`), and the portenv CLI. No port reachable from outside is opened.
- **SFTP storage for every box**, on the server too. Boxes back up and restore over SFTP with the storage key served from memory by the agent; the server's host key is pinned.
- **Host-side restic** (lease checks, listing, lease tags, keys, retention) runs on the machine, not in the box. On SFTP servers it goes through restic's REST server on the server's loopback (127.0.0.1:7422), forwarded over the storage account's reused SSH connection to a unix socket in a private directory. The storage key may forward to that one port only; each box has its own REST user, with only its bcrypt hash on the server.
- **Per-machine repository keys**: `move` sends the key once over SSH's stdin; the server adds its own key and never stores the Mac's.
- **Offline resume** when this machine's state shows the home equals the last save it made or restored; saves wait ("Offline · will save later").
- **Saves**: complete once restic's summary reports the snapshot ID and it is recorded (no listing afterwards); created already carrying the lease tag; `--key-hint` so restic opens the repository with this machine's key first. `portenv housekeep` clears leftover lease tags and applies retention, never removing the current save.
- **Traces** (`PORTENV_TRACE=1`) for every phase of resume, save and close, including restic backup's sub-phases.
- **`own-route` CI job**: the own-route journey with every Portenv-hosted endpoint blocked (ADR 0008, G3).

## Phase 0 gate (final round, 2026-10-08)

AWS t4g.small, eu-west-3, Ubuntu 24.04 arm64. Link from the Mac: 20.05 Mbit/s up, 40 ms round trip, SSH setup 0.62 s.

| Check | Result |
| --- | --- |
| Mac → server → Mac, checksums of `/home` | match both ways; apt packages replayed; home on the encrypted volume |
| Resume, storage reachable (5 runs) | median 3.1 s, worst 3.23 s (budget 5 s) |
| Resume, offline (5 runs) | median 2.22 s, worst 2.34 s (budget 5 s) |
| Close with a 5 MB unsaved change | 8.52 s at 20.05 Mbit/s (budget 15 s) |
| Freshness, continuous editing, autosave every 30 s | at most 41.1 s behind (budget 60 s) |
| No new listening port; REST server on loopback only; LUKS key root-only | pass |

One check in that run failed on a bug in the check itself (an unescaped `$` in a regular expression); the corrected check and a negative test passed against the same server state.

## Found and fixed on the way

- uid 990 was taken on Ubuntu (fwupd-refresh), so storage became one SFTP account for every box; sshd could not read authorized keys in a root-only directory; the SFTP helper directory was unreadable; ssh inherited stdin and hung; restic's cache was wiped at every start (now a volume); the SSH control path was too long on macOS; a local image digest was pinned and could not be pulled on the server.
- Saves listed the repository again after backing up and untagged every older save: both removed. restic tried every key with scrypt: fixed with the key hint.
- The online resume budget missed by about 2 s over SFTP (listing plus lease tag at about 40 round trips each); the REST server spike brought it under budget.
- The reachability probe now runs while the box starts, and the agent is polled from 50 ms instead of every second.
- Close varied from 8 to 17 s: almost all of it is the box's SFTP upload, about one 32 KB write per round trip. Recorded for 2.6, where box backups move to REST.

## Not verified yet
