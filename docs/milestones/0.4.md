# Milestone 0.4: docker driver and temporary CLI

Date: 2026-10-07

## What exists now

- **Where restic runs (ADR 0005):** inside the box, started by `portenv-agent` for each run, as the dedicated user `portenv-sync` with file capabilities, which makes it non-dumpable. The password arrives on stdin and reaches restic on a pipe; the agent runs only allow-listed commands and only the restic build whose SHA-256 is baked into it. The conditions (no `CAP_SYS_PTRACE`, `CAP_SYS_ADMIN` and the rest, never privileged) are checked by the agent at every start.
- **`core/driver/docker`**: the docker driver. Fresh container from the box's spec at every start (only `/home`, a named volume, persists); never privileged, no added capabilities, no host namespaces.
- **`core/driver/drivertest`**: the conformance suite every driver must pass.
- **`core/keys`**: repository keys in the macOS Keychain (this device only, never synced) or a root-only directory on servers.
- **`core/sync`**: an `Executor` seam; `AgentExecutor` runs restic and path checks inside the box.
- **`portenv` CLI (temporary)**: `init`, `resume [--take-over]`, `save`, `point`, `close`, `status`, `history`, `move --to HOST`.

## Tests

- Driver conformance against Docker Desktop: lifecycle, logs, stats, exec with stdin and exit codes, `/home` surviving restarts and Destroy, a fresh root file system at each start, a missing home reported as FAILED.
- `TestAgentRefusesForbiddenCapabilities`: boxes started with `CAP_SYS_PTRACE`, `CAP_SYS_ADMIN` or `--privileged` refuse to become ready and name the capability. `TestHostConfigKeepsIsolation` guards the driver's container settings.
- `tests/e2e/restic-isolation.sh`: 16 probes (environment, pipe, command line, memory scan, ptrace, as root, root as restic's uid, and a lane user, plus a disk search) all denied. The control run with restic as plain root leaks the password to root four ways.
- `tests/e2e/two-machines.sh`: two simulated machines, one storage: new box, lease refusal, A → B → A with matching checksums of `/home`, `apt-packages.txt` replayed after a move, take over, rule 4 keeping unsaved work as orphaned.

## Found and fixed on the way

- **Orphans counted as the current save.** After rule 4 the orphaned save is the newest snapshot by time, so the lease looked free and the next machine would have restored the stale orphan. Now the current save is the newest non-orphaned snapshot. A regression test covers it, and the model test now checks who holds the lease after every step and includes crash-and-reopen steps that reach rule 4 (it fails with the bug reintroduced).
- `CAP_DAC_READ_SEARCH` is outside Docker's default set, so restic with it fails to exec; `CAP_DAC_OVERRIDE` covers reading every home.
- Docker Desktop's engine hung during a rebuild and was restarted.

## Demo

```sh
make image && make driver-test && make e2e
bin/portenv init demo --image portenv/toolbox-node:dev
bin/portenv resume demo          # rule 1: new box
bin/portenv point demo && bin/portenv history demo
bin/portenv close demo
```
